## Blocker

### QA-001: Every Models list, item page and create form is broken (field views are off by one)
- **Area:** dashboard
- **URL:** `/dashboard/<any list>` (all 78), `/dashboard/<list>/<id>`, `/dashboard/<list>/create`
- **Steps:**
  1. Sign in as admin.
  2. Open `/dashboard/practice-areas`, or any entry under **Models**.
  3. Open `/dashboard/public-site-policies/create`.
  4. On a matter page, click **Fields** (`/dashboard/matters/<id>`).
- **Expected:** As in E-commerce, lists load, item pages open and create forms show the right controls.
- **Actual:**
  - All 78 lists show "Failed to load items: Unable to complete the request." I checked every list link in the sidebar.
  - Item pages say "The item with ID … doesn't exist", even for the matter I had just opened.
  - Create forms render the wrong control for each field:
    - checkboxes (`publicAccountsEnabled`) show as "Pick a date and time" date pickers
    - text fields (`privacyNotice`, `aboutStatement`) show as a locked "Auto-generated / autoincrement" id field
    - the select (`status`) shows as a "Set status" password-style button
- **Cause:**
  - `features/keystone/view-order/index.ts` lists `"id"` first. The Law Firm generator emits the id view; E-commerce's `VIEW_ORDER` starts with `"relationship"`.
  - `features/dashboard/views/getFieldTypeFromViewsIndex.ts` (identical to E-commerce) also prepends `'id'`.
  - So every `viewsIndex` resolves one slot too early: text→id, select→password, checkbox→timestamp. The wrong field types then produce invalid list queries.
  - Fix either the generator (`features/keystone/view-order/generate-view-order.ts`, `fieldViewOrder`) or the prepend, then regenerate.
- **Why it's a blocker:** many day-one records have no platform screen, so Models is the only way to manage them, and it's dead:
  - Public Site Policy, so the site can't be published (QA-003)
  - practice-area publishing
  - Rate Cards (QA-005)
  - Payments (QA-006)
  - Trust Accounts (QA-007)
  - Roles (QA-015)
  - Document Versions (QA-012)
  - Courts, Retention Policies, Integration Connections
- **Likely files:** `features/keystone/view-order/index.ts`, `features/keystone/view-order/generate-view-order.ts`, `features/dashboard/views/getFieldTypeFromViewsIndex.ts`

### QA-002: Online consultation booking can never open for a real firm
- **Area:** storefront
- **URL:** `/consultation`, `/practice-areas/<slug>`
- **Steps:**
  1. Read `features/keystone/mutations/customerConsultations.ts`.
  2. On production, open `/consultation`. It shows "Choose an appointment" over an empty area. There's no published practice area, which needs the Models fix.
- **Expected:** Once a firm publishes its policy, its practice areas and its first-contact notice, a prospect can create an account, pick a time and book. This is the storefront's main flow.
- **Actual:**
  - `requireConfiguredConsultationCalendar(mode)` throws for every `mode !== 'fixture'`. The message is "Online consultation scheduling is unavailable until the firm configures a reviewed calendar."
  - Both `consultationAvailability` and `bookClientConsultation` call it.
  - No calendar or hours configuration exists anywhere in the product.
  - The only admitted mode is the owned offline fixture, and onboarding disables that on production ("Sample records are available only on an owned offline test database").
  - So no deployed firm can ever take a booking.
- **Note:** I couldn't run the live booking path end to end, because the site can't be published (QA-001 and QA-003). This finding is from the code.
- **Likely files:** `features/keystone/mutations/customerConsultations.ts:187-191`, `:200`, `:277`; `CONSULTATION_HOURS` in the same file
